## Findings addressed

1. **High - profile handoff could silently drop favorites.**
   `src/lib/profile-transfer.js` skipped oversized values or submitted a partial
   snapshot after a storage-read error. A port move could then open without the
   omitted data. Capturing the snapshot now fails as a whole, so Settings does
   not change the port. A failed fresh-origin restore removes keys it had just
   written so a later attempt is possible. Existing profiles are not overwritten.
2. **Medium - valid native backups could become unreadable.**
   Profile values were bounded by raw UTF-8 size, but the request/file bounds did
   not account for JSON escaping. Native request/read bounds now accommodate the
   worst-case encoded size while retaining the 2 MiB raw-value safety check.
3. **Medium - thumbnail queue slots could remain occupied indefinitely.**
   Image requests waited for load/error/abort with no watchdog. A 20-second
   per-attempt timeout now clears a stalled request and releases the slot;
   existing bounded retries and playback priority are retained.
4. **Medium - shutdown could stop workers without exiting.**
   Process exit was scheduled only after sending the HTTP response. A client
   disconnect could throw before that step. Authenticated shutdown now schedules
   exit in `finally`, including response/cleanup exceptions. A follow-up candidate
   log showed an accepted shutdown despite the UI offering Retry, with no app
   processes left running. Shutdown now acknowledges before background cleanup,
   schedules only one exit worker, and never presents Retry after acceptance
   merely because DOM/native-window cleanup failed.
5. **Low - zero sidebar counts were blank.**
   Count rendering now displays `0` explicitly.

## Issue #1 requests implemented

- **Local M3U/M3U8 import:** Library -> My Playlists, TV/radio default, playlist
  selector, local title/group search, media filter, same-name replacement with
  confirmation, and explicit removal. Duplicate channel URLs/types within a list
  are deduplicated; aggregate playlist view also deduplicates shared channels.
- **Add link:** paste a direct channel URL or select Online M3U playlist, with
  an optional name. Online lists use the existing bounded safe fetcher and
  resolve relative stream/logo URLs against the final redirected playlist URL.
  Re-adding the same URL updates its list without removing saved favorites.
- **Favorites organization:** independent All/Radio/TV/Video/Audio filtering and
  local search, without changing the public-catalog search. Choices persist for
  the session, not across restarts.
- **Persistence:** imported lists live in portable `state/playlists.json`, outside
  catalog cache and browser-origin storage. Writes use the existing atomic-write
  helper. Failed imports/removals do not change the frontend collection. Invalid
  existing playlist data is not overwritten. Removing a list keeps favorites.
- **Network boundary:** files/direct links are saved without fetching channel
  URLs; online playlist imports fetch only the explicitly submitted list URL.
  Public HTTP(S) playback/artwork still uses existing authenticated registries,
  DNS-pinned relays, redirect checks and private-address rejection. This does not
  add proxy allowlists or weaken media security.
- **Scope:** live channel lists, not local media libraries or provider-account
  integration. No remote playlist URL subscription, auto-refresh, or playlist
  catalog inside Grid/Tuner/Discovery yet. HLS manifests are not misinterpreted
  as collections of channels. See the updated user guide for supported metadata
  and explicit file/storage safety limits; the public catalog remains uncapped.

## Initial candidate risks / release gates (superseded by release record)

- **Medium - silent browser-storage write failures remain.**
  `persistFavorites()` and several preference writers only log quota/access
  errors. The in-session UI may show a saved favorite that did not persist.
  Native automatic profile backup is also bounded and swallows background
  failures; manual port changes now fail safely, but oversized profiles still
  need a clearer backup warning or a separate native favorites store. This audit
  does not migrate or modify existing favorites.
- **Permission blockers resolved:** the initial `spawn EPERM` and temporary
  directory access failures no longer occur after the permission change. Normal
  test suites, frontend build, and EXE packaging have now completed successfully.
